# dosar-radar

**Знайди свою справу в наказах про румунське громадянство — в одному пошуковому рядку.**

Пошуковий індекс по всіх наказах *art. 11* Міністерства юстиції Румунії:
**315 173 номерів справ**, витягнутих із **2 214 PDF-наказів** за 2018–2026 роки —
станом на липень 2026, і більшає з кожною синхронізацією.

## Проблема

Якщо ви подали документи на румунське громадянство за **статтею 11**, рішення щодо вашої
справи публікується на [cetatenie.just.ro](https://cetatenie.just.ro/ordine-articolul-1-1/)
— як **PDF-додаток до наказу міністра**. Без пошуку. Без покажчика. Без сповіщень.

Таких PDF — понад дві тисячі. Щоб дізнатись, чи є ваш номер справи хоч в одному з них,
передбачається відкривати їх по черзі та читати.

`dosar-radar` робить це один раз і перетворює на пошуковий рядок.

## Що вміє

| | |
|---|---|
| 🔎 **Пошук за номером справи** | `29293/2023`, `48031/RD/2023` чи просто `29293` — знаходять ту саму справу |
| 📄 **Повний список наказів** | Дата, номер, кількість справ і посилання на оригінальний PDF |
| 🗂 **Справи всередині наказу** | Відкрийте будь-який наказ і побачите всі номери справ у ньому |
| 🔄 **Оновлення в один клік** | Забирає нові накази й розбирає лише те, що ще не розібране |
| 🖥 **CLI** | Той самий пошук і синхронізація без вебу — зручно для скриптів і cron |
| 🐳 **Спочатку Docker** | `make up` — і воно працює; дані живуть в іменованому томі |

## Швидкий старт

```bash
git clone https://github.com/paulfcdd/dosar-radar.git
```

```bash
cd dosar-radar && make up
```

Інтерфейс — на **http://localhost:8000**, але база спочатку порожня. Наповнюємо:

```bash
make sync
```

Перша синхронізація качає й розбирає ~2 200 PDF. Залежно від мережі це приблизно
**20–40 хвилин**; кожен наступний запуск чіпає тільки нові чи раніше невдалі накази й
завершується за секунди. Прогрес видно у вебі або через `make logs`.

Хочете спершу переконатись, що все живе?

```bash
make sync-fast
```

Розбере лише 20 найсвіжіших наказів.

## Як воно влаштоване

```
cetatenie.just.ro
       │
       │  ① HTTP-сесія, яка розв'язує proof-of-work челендж сайту
       ▼
   сторінка ──② розбір HTML──▶ 2 214 наказів (дата, номер, посилання на PDF)
       │
       │  ③ качаємо PDF, по 4 паралельно
       ▼
   pdfplumber ──④ регулярка + фільтр шуму──▶ 315 173 номерів справ
       │
       ▼
    SQLite (WAL) ──▶ Flask UI  ·  CLI
```

Чотири місця варті окремої уваги.

**① Челендж.** Сайт міністерства стоїть за антибот-сторінкою, яка замість вмісту віддає
`503` із JavaScript-задачкою. Це proof of work у стилі hashcash: сторінка містить
hex-токен `c`, і клієнт має підібрати лічильник `i` такий, що `SHA1(c + str(i))` має байт
`0xb0` на позиції `n` і `0x0b` на `n+1`, де `n` — перший шістнадцятковий символ токена.
Відповідь повертається як cookie. [`session.py`](cetatenie/session.py) розв'язує це чистим
Python і кешує cookie на весь прогін — без браузера й без JS-рушія.

Обфускований скрипт ротує свій масив рядків на різну кількість кроків у кожній відповіді,
тож розбір за позиціями ламається протягом доби. Замість цього ролі визначаються **за
вмістом**: 40-символьний hex — це токен, рядок, що закінчується на `=`, — префікс cookie.

**② Список наказів.** Накази згруповані під звичайними `<p>` із роком, а не вкладеною
розміткою, тож [`scraper.py`](cetatenie/scraper.py) обходить `<p>`/`<li>` по порядку й несе
поточний рік як стан.

**③ Розбір PDF.** Читаємо через `pdfplumber`. Складність у тому, що гола регулярка на
`номер/рік` ловить і посилання на закони в шапці та підвалі — `Regulament 2016/679`,
`Legea 21/1991`, — які номерами справ не є. Фільтр шуму викидає такі рядки до вилучення.

**④ Ключі пошуку.** Номери зустрічаються у двох формах: `16545/2024` і `48031/RD/2023`.
Кожна справа зберігається двічі — як надруковано (`case_number`) і зведена до `номер/рік`
(`search_key`), — тож `48031/2023` знаходить і варіант із `RD`, а голе `29293` дає збіги
за всі роки.

## Команди Makefile

Запустіть `make` без аргументів, щоб побачити цей список будь-коли.

| | |
|---|---|
| **Docker** | |
| `make build` | Зібрати образ |
| `make up` | Підняти веб на :8000 |
| `make down` | Зупинити (том із даними лишається) |
| `make logs` | Дивитись логи |
| `make sh` | Shell усередині контейнера |
| **Дані** | |
| `make sync` | Повна синхронізація — список + усі нерозібрані PDF |
| `make sync-fast` | Пробний прогін на 20 наказах |
| `make stats` | Скільки наказів і справ у базі |
| `make search Q=…` | Знайти номер справи |
| `make db-export` | Знімок бази з тому у `./data.sqlite3` |
| `make db-import` | Залити `./data.sqlite3` у том |
| `make clean` | Знести контейнери **разом** із томом бази |
| **Без Docker** | |
| `make venv` | Створити `.venv` і поставити залежності |
| `make dev` | Запустити Flask локально |

Змінні: `PORT` (типово `8000`), `WORKERS` (типово `4`), `Q` для `make search`.

### Перенести базу на іншу машину

Синхронізована база важить ~36 МБ і свідомо **не** лежить у git. Щоб не синкати з нуля
деінде, перенесіть файл:

```bash
make db-export && scp data.sqlite3 other-host:/path/dosar-radar/
```

Далі `make db-import` на тому боці. Обидва таргети йдуть через `VACUUM INTO` і прибирають
залишкові WAL-файли: якщо копіювати живу базу SQLite руками, свіжі записи тихо губляться —
або взагалі відкочуються.

## Налаштування

| Змінна | Типово | Що означає |
|---|---|---|
| `CETATENIE_DB` | `./data.sqlite3` (`/data/data.sqlite3` у Docker) | Шлях до бази |
| `PORT` | `8000` | Порт, який публікує compose |
| `BIND` | `127.0.0.1` | Інтерфейс, на який біндить compose. За реверс-проксі не чіпайте; `0.0.0.0` — лише якщо справді треба виставити застосунок напряму |

Контейнер запускає `gunicorn` із **одним воркером і вісьмома потоками** — свідомо: прогрес
фонової синхронізації живе в пам'яті процесу, тож із кількома воркерами `/sync/status`
відповідав би то з процесу, що качає PDF, то з іншого, який про це нічого не знає.

## Структура

```
app.py                 Flask-маршрути — список, пошук, наказ, синхронізація
cli.py                 Командний інтерфейс
cetatenie/
  session.py           HTTP-сесія + розв'язувач proof-of-work челенджа
  scraper.py           Розбір HTML-списку + вилучення справ із PDF
  db.py                Схема SQLite і запити
  sync.py              Оркестрація, пул потоків, стан прогресу
templates/             Серверний рендеринг, без збірки й без JS-фреймворків
```

Жодного фронтенд-тулчейну, ORM чи міграцій — близько 600 рядків Python загалом.

## Чесно про обмеження

- **Це не офіційне джерело.** Остаточна відповідь — завжди PDF на cetatenie.just.ro, на який
  сервіс дає посилання в кожному результаті. Номери вилучаються регуляркою з документів, які
  ніколи не призначались для машинного читання.
- **3 накази з 2 214 не розбираються.** Список самого міністерства посилається на три PDF,
  які віддають `404`. В інтерфейсі вони позначені як `error` із причиною.
- **Скановані PDF було б пропущено.** Накази без текстового шару позначаються помилкою, а не
  тихо дають нуль справ. Зараз таких немає, але перевірка є.
- **Не зловживайте.** Синхронізація ручна й типово качає в 4 потоки. Будь ласка, не
  накручуйте `WORKERS` і не гатьте по сайту державного органу.
